One more proposal

I think we should create a Project Bible before writing the first line of code.

This will be a single master document (around 80–120 pages by the end of the project) that contains every architectural decision, sprint plan, API contract, database schema, UI flow, and engineering guideline. Throughout development, we'll keep updating it so it becomes the complete reference for the project.

I believe this will make our collaboration much smoother than jumping straight into coding.

I also have a few improvements I'd like to introduce that will make your project even stronger than typical collaborative whiteboards:

A plugin-ready tool architecture so adding new drawing tools doesn't require changing the core canvas engine.
Separate rendering, interaction, and synchronization layers to keep the codebase maintainable as features grow.
A unified object model so both Infinite Canvas Mode and Document Mode share the same drawing engine instead of maintaining two separate implementations.
A versioned synchronization protocol to make future features like offline editing and board history easier to implement.

I think this project can become one of the strongest portfolio pieces you've built, and I'll help you approach it with the same discipline and planning used on real engineering teams.
